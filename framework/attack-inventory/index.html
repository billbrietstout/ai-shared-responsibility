Framework in practice

Attack inventory

50 published attack classes against AI models, LLM applications, agents, and the business processes agents run. Each class states a failure mode and lists MITRE ATLAS, MITRE ATT&CK, OWASP, FINOS, CWE, arXiv, and CVE ids. Every id was checked against a pinned catalog version or its source record on 1 October 2026. The file assigns no owners: 38 classes link to the SRF threat crosswalk, which names the accountable persona, and 12 have no crosswalk row yet. Seven business-process classes also link to vertical profile controls.

Use

Cite checked ids instead of recalled ones

The claims test builds a table of published attack classes in its C-attacks step. Pack 1.0.9 reads this inventory by default and builds rows from it first, so those rows carry ids resolved against ATLAS v2026.08, OWASP LLM Top 10 2025, OWASP Agentic AI Threats and Mitigations v1.1, OWASP GenAI Data Security 1.0, FINOS AI Governance Framework v2, ATT&CK Enterprise 19.2, or CWE 4.20. Classes the inventory lacks still get ids from model memory, marked unresolved_unpinned. When a run names an industry pilot, the pack also selects classes whose vertical_controls cite that vertical.

A threat model or red-team scope can start from the same list, then follow a class's srf_crosswalk ids, where present, into /data/threats.json for the SRF layer and the accountable persona per operating model. The inventory sets no severity and holds no procedures: each entry says who loses what, under what condition.

Seed check

What checking the seed table changed

31 entries came from the attack table of a claims-test run against a draft paper, where every catalog and paper id had been filled from memory. Checking them against their sources changed refs on 11 entries.

  • All 14 arXiv ids in the seed table resolve, and each first author matches the table.
  • All 13 ATLAS ids in the seed table exist at v2026.08 and keep their names in v2026.09. Six seed rows cited a parent technique or a looser fit where ATLAS has a narrower one; zero-click exfiltration, for example, now maps to AML.T0077 LLM Response Rendering. Sandbox escape had no ATLAS id and now maps to AML.T0105 Escape to Host.
  • ATLAS case study AML.CS0059 tags the EchoLeak injection step as AML.T0051.002 Triggered. The seed table tagged it .001 Indirect. EchoLeak now sits under zero-click exfiltration.
  • MCP tool poisoning had only a blog post. ATLAS case study AML.CS0054 cites that post and gives it a stable id; AML.T0109 and CVE-2025-54136 cover tool definitions that change after approval.
  • Injection carried by telemetry into LLM-assisted triage was mapped by analogy, with no paper. Three 2026 arXiv papers show log fields acting as attacker-controlled content that an LLM triage tool reads. That is the data-channel case AML.T0051.001 Indirect covers, so the ref is now graded exact.
  • The OWASP Agentic AI Threats PDF now served is v1.1 (December 2025). It adds T16 and T17; the seed's T1, T3, T7, T8, T9, T10, and T11 keep their titles.
Business process

What the process classes in 0.2.0 found

Version 0.2.0 adds eight classes in which an AI system or agent moves money, changes a vendor or beneficiary record, or passes an approval step: payment diversion, invoice or purchase order alteration, approval gate bypass, master data change, workflow rule injection, false status reporting, partner agent hijack, and deepfake approver impersonation.

  • Two of the eight have an exact catalog entry. Approval gate bypass matches FINOS AIR-SEC-024 Agent Action Authorization Bypass and CWE-841 Improper Enforcement of Behavioral Workflow. Deepfake approver impersonation matches AML.T0052.001 Deepfake-Assisted Phishing. For the other six, closest is the best grade available.
  • ATLAS v2026.08 names the harm (AML.T0048.000 Financial Harm) and the tool step (AML.T0053 AI Agent Tool Invocation). It has no technique for changing a business process. ATT&CK T1565 Data Manipulation and its three sub-techniques say the adversary may aim to affect a business process, so ATT&CK Enterprise 19.2 is now pinned for those refs.
  • ATT&CK 19.x revoked T1656 Impersonation and moved it to T1684.001. ATLAS v2026.08 AML.T0073 Impersonation still links to T1656, so a ref recalled from memory or copied from ATLAS would cite the revoked id.
  • Three process classes have no row in /data/threats.json: approval gate bypass, false status reporting, and deepfake approver impersonation. That file keys rows by OWASP AI Exchange or DSGAI ids and has no L1 row for approvals. Approval gate bypass reaches L1 through vertical_controls instead: finance SRF-L1-DEV-004 requires a named human business owner for each process an agent acts in. No vertical control checks who an approver is, so the deepfake class has none.
  • Vendor master data and invoices are L2 records, so those two classes cross-walk to DSGAI05 Data Integrity & Validation Failures. The decision to accept a changed record still belongs to the L1 process owner.
Version 0.3.0

Where the new classes split from their neighbors

Version 0.3.0 adds five classes from failure modes that the AITBM use-case pages describe. Three of them split from an existing entry, and each split follows a difference in what a defender has to check.

  • MCP tool poisoning covers a tool definition that a connected server serves, or changes after approval. Agent skill poisoning covers a package of instructions and code that a user installs from a registry, where install counts and look-alike names decide what gets installed. ATLAS uses AML.T0110.000 for both, so a claims-test run may select both entries for one claim. AML.CS0049 moved from MCP tool poisoning to skill poisoning.
  • Indirect prompt injection covers content an agent reads while it works on a task. A coding agent's rules or configuration file loads when the project opens and applies to every later task; CVE-2026-12957 ran commands from project configuration before the developer typed anything. Both entries cross-walk to the same threats.json row, because one application team decides what the agent accepts as instructions.
  • Agent config credential exposure is about secrets stored in readable files. An exposed control interface hands over the agent's tools even when no secret is stored in plain text. AML.CS0048 shows both on the same hosts; it is cited under the control interface because ATLAS records the entry point as AML.T0049 Exploit Public-Facing Application.
  • Agent session smuggling and the malicious LLM API router split from no entry. DSGAI06 names inter-agent context smuggling, but ATLAS v2026.08 has no technique for a victim agent that receives hidden turns. The router class rests on one measurement paper, cites no incident, and has no threats.json row.

Known limits

What this version cannot answer

  • An AI agent ran every check in this version. reviewed_by is null on all 50 entries until a person confirms them.
  • A verified paper ref means the arXiv id resolves and the title and first author match. Abstracts were read for the three telemetry-triage papers, AgentDojo, and Agent Security Bench. The Agents of Chaos cases cited for display-name spoofing and false self-reports were not reread.
  • Nine classes have no exact catalog entry. Three predate 0.2.0: deceptive agent self-report (OWASP Agentic T7 is the closest), observability-plane evasion (AML.T0081 covers a disabled setting, not a starved guardrail), and the token-length side channel (no ATLAS, OWASP LLM, or OWASP Agentic entry). The other six are business-process classes; the section above names them.
  • Twelve classes have no row in /data/threats.json, so the inventory cannot name an SRF layer or accountable persona for them from that file: agent memory poisoning, hallucinated package squatting, sandbox escape, deceptive agent self-report, repudiation by log tampering, observability-plane evasion, approval fatigue, the token-length side channel, approval gate bypass, false process status reporting, deepfake approver impersonation, and the malicious LLM API router. Adding an L1 row for approval processes would need a source catalog id, because that file mints none of its own.
  • vertical_controls is filled only on the eight business-process classes. Earlier classes such as excessive agency and approval fatigue likely match finance and insurance controls too, but no one has checked those links.
  • Bank payment-system intrusions with no AI step, such as the 2016 Bangladesh Bank theft, have no entry. The US Department of Justice page that would anchor that case returned a bot-check page with no text on 1 October 2026, so it could not be verified.
  • BIML LLM24 ids are not mapped. They name risk areas broader than these classes, and choosing between them needs a reviewer.
  • ATLAS v2026.09 is out and adds AML.T0129 Triggers in Multimodal Inputs, which may fit multimodal instruction injection more narrowly. The pin stays at v2026.08; every cited id keeps its name in v2026.09.
  • The list started from one claims-test attack table, six classical weaknesses, and eight business-process classes. ATLAS techniques outside those topics, such as AML.T0015 model evasion against classic ML classifiers and AML.T0041 physical-environment attacks, have no entry of their own. KYC onboarding fraud with deepfakes (AML.CS0033, AML.CS0034) is also unlisted.
  • Three AITBM use-case pages describe failure modes that still have no entry: a computer-use agent that clicks a screen position after the page has replaced the control it chose, a safety monitor whose tokenizer drops characters that the main model reads, and opaque reasoning blocks that another user can replay to recover hidden reasoning. Their primary sources have not been opened.
  • Agent session smuggling has only a proof of concept; Unit 42 reports no use in the wild.
  • Fifteen incident refs are URLs to news, vendor, or researcher reports with no CVE or case-study id, so each needs a fresh fetch at every review. The macOS.Gaslight ref shows an implant aimed at an LLM triage tool, but its authors did not test an LLM, so it shows intent and not a working bypass.
Maintain

Change, verify, export

Edit the JSON, bump inventory_version (patch for a ref fix, minor for a new entry, major for a removed field or changed id), and add one changelog line naming the id and the reason. Then run the verifier. It fails on a dangling id, a ref whose catalog version differs from the pin, a vertical control id missing from /ids.json, a verified ref with no check date or method, or an em dash in any text field. It warns when a newer catalog release has been seen or a URL ref is more than 180 days old. 

python3 build/verify_attack_inventory.py

A claims-test run reads the whole file unless it is given an export. To limit a run to the draft's topics, export them and attach the result. Rows are numbered ATT-01 upward after the filter; draft overlap stays null for the run to judge. 

python3 build/export_attack_inventory.py --topics telemetry,MCP --format md
python3 build/export_attack_inventory.py --scope agentic --out attacks.json
python3 build/export_attack_inventory.py --topics payment,approval --vertical finance

Recheck the inventory when ATLAS or ATT&CK Enterprise publishes a release, when FINOS tags a new AI Governance Framework version, when OWASP revises the LLM Top 10 or the Agentic AI Threats document, when a CoSAI WS2 draft cites a new incident, or when a claims-test run finds a class missing here.
