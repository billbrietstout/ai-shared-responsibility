Implementation 12.3.2: Version Control and Rollback Procedures

Maintain a strict version history of all AI-generated operational logic. Record why each version replaced the one before it. Keeping every version and its reasons has a storage and administration cost, so how long superseded versions are kept is for the organization to decide, within any regulatory or contractual obligations. Define who may order a rollback and under what conditions. Keep a known-good, human-verified configuration or procedure, identified by version or hash, available as a fallback in the event of an SI-generated logic failure. Periodically test restoration of the known-good version, to confirm that the function operates as intended after it is restored. For PLC logic and configurations, as an example, keeping the known-good backup offline on secured removable media can support fast recovery where the online copy has been altered.

Decisions for the Organization:

  • Who may order a rollback, and under what conditions? (see the Secure effect in Task 12.3: Manage Operational Continuity and Resilience for Generated Artifacts)
  • How often is restoration of the known-good version tested, and where is the backup kept?

References:

  • Guidance NIST SP 800-53r5, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement CM-2(3), Retention of Previous Configurations, retains a defined number of previous baseline configurations, including configuration files and associated documentation, to support rollback, which is the known-good fallback this Implementation keeps for AI-generated operational logic. Control enhancement CP-9(2), Test Restoration Using Sampling, restores selected system functions from backup information during contingency plan testing, to give assurance that those functions can be restored correctly. This supports testing that the known-good fallback can be restored.
  • Guidance Iranian-Affiliated Cyber Actors Exploit Programmable Logic Controllers Across US Critical Infrastructure, joint Cybersecurity Advisory AA26-097A, April 2026, from the FBI, CISA, NSA, EPA, DOE and the US Cyber Command Cyber National Mission Force. Under Mitigations, after actors altered PLC project files, it recommends creating and testing backups of PLC logic and configurations and storing them offline on secured removable media to enable fast recovery. This bears on where the known-good fallback for generated PLC logic is kept.
  • Guidance NIST IR 8183A Volume 2, Cybersecurity Framework Manufacturing Profile Low Impact Level Example Implementations Guide: Process-based Manufacturing System Use Case, September 2019, from NIST. Section 3.6.12.4, PLC Logic Recovery, restores “the PLC logic back to a known state in case of compromise or corruption” from the engineering workstation, and warns that “The manufacturing system must be in a non-operational state when this recovery is performed.” This bears on the PLC example and on planning when restoration of the known-good version can be tested.
