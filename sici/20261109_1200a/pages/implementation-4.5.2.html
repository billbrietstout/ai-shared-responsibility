Implementation 4.5.2: Establish Deterministic Boundary Constraints for Automated Regimes

Identified human-out-of-the-loop operational regimes should include independent, non-AI deterministic safety wrappers detailed in Task 3.2: Implement Independent Guardrails for SI Outputs. Make these wrappers as independent of the SI system as practical. Where they share sensors, power, or networks with it, record which. Ensure that these physical process boundaries have total authority to block unsafe autonomous commands, execute fallback states per Implementation 3.2.3: Specify Fail-Safe States and Fallback Behavior, and log the event prior to subsequent human administrative review. Where practical, and in proportion to the consequences, keep this boundary logic small enough to be analyzed and tested independently of the SI system it constrains and, where the severity of consequences warrants, formally verified, as for the watchdog logic in Implementation 2.2.2: Deploy “Watchdog” Controllers.

Decisions for the Organization:

  • At what severity of consequence is the boundary logic formally verified, and who has the expertise to do it?

References:

  • Guidance NIST SP 800-82r3, Guide to Operational Technology (OT) Security, September 2023, from NIST. Section 2.3.7, Safety Systems, describes a safety instrumented function as sensors, logic solvers and final control elements that bring a system to a safe state when predetermined thresholds are violated. It notes that a safety instrumented system is often independent of the basic process control system, so that a failure of the latter does not impair it. That is the established process-industry form of the independent boundary this Implementation asks for.
