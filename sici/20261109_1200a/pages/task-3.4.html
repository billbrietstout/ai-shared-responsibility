Task 3.4: Monitor for Anomalous SI Behavior

Define policies and procedures for detecting acute, undesired, unexpected, and unusual AI system behavior, as continuous, real-time monitoring that complements the scheduled batch evaluations in Implementation 2.3.4: Recurrent Risk Evaluations and operates against the thresholds defined in Implementation 3.3.2: Establish Maximum Drift Thresholds. This includes violations and near violations of constraints defined in Implementation 3.2.2: Define and Independently Enforce Deterministic Operational Constraints as well as other metrics such as unusual changes in performance or output, even if they remain within safe constraints. The SI system being monitored should not be able to modify or suppress the monitoring, telemetry or alerts that concern its own behavior.

Detection of regular anomalous behavior should also feed into the estimation of drift velocity in Implementation 2.3.4: Recurrent Risk Evaluations. This includes distinguishing, where feasible, between anomalies likely caused by incidental drift or error and those consistent with deliberate interference. The pattern of change can be one indicator. Slow, gradual change in performance is more often consistent with drift, while abrupt change in one or more dimensions is more often consistent with an attempt at compromise. Neither pattern settles the question on its own.

Main Trustworthiness Contributions:

  • Reliable: Contributes the continuous check that the AI system still performs as it did when it was accepted, covering near-violations and changes in output that stay inside the safe constraints, together with confirmation that the safety wrapper is still functioning, whether it has stopped through fault, misconfiguration or tampering, so degradation arising between scheduled evaluations is caught. This Task does not cover setting the limits those observations are judged against, which Implementation 3.3.2: Establish Maximum Drift Thresholds covers.
  • Secure: Contributes the runtime separation of an anomaly consistent with drift or error from one consistent with deliberate interference. This Task does not cover monitoring access boundaries or privilege escalation by AI entities, which Task 5.4: Implement Continuous Monitoring of SI Entities Against Access and Action Boundaries and Expectations covers.

Trustworthiness Side Effects to Consider:

  • Privacy-Enhanced: Observing output patterns means retaining outputs, and for an AI system working on records or documents those outputs carry whatever the source carried. Implementation 10.1.3: Forensic Integrity and Privacy-Preserving Log Partitioning sets the masking and partitioning arrangements for telemetry that holds sensitive material.
  • Secure: The observability requirements, baselines, and deviation ranges set here describe what is watched and what counts as normal. An attacker who knows them could keep activity inside the normal range, or act through something that is not observed. Protecting them is a matter for the organization’s existing information classification and handling practice. The telemetry itself is protected under Practice 10: Implement Multi-Tiered SI System Logging and Audit Capabilities.

Trustworthiness Tensions to Balance:

  • Secure versus Reliable: Where the cause of an anomaly is clear, the response follows from it. Where one observation could be drift or could be interference, the reliability response of recalibrating or widening the baseline and the security response of preserving state and investigating point in opposite directions, and handling manipulation as drift adapts the AI system toward the manipulated distribution. One way to balance this is to hold the baseline and escalate under Implementation 3.4.4: Define Runtime Anomaly Escalation Procedures until the cause is established; others include preserving the evidence while continuing to operate under tightened constraints.

Related AI RMF Subcategories Include:

  • MEASURE 2.4 (on monitoring deployed AI systems): This Task defines the observable behaviors, operational baselines and deviation ranges by which a deployed AI system is watched continuously, including whether its validation controls are still functioning; it does not cover the scheduled evaluation that runs alongside that monitoring. For that, see for example Implementation 2.3.4: Recurrent Risk Evaluations.
  • MEASURE 3.1 (on tracking known and emerging risks): This Task tracks emergent behavior against an operational baseline, and distinguishes, where feasible, anomalies caused by drift or error from those consistent with deliberate interference; it does not cover tracking risks that leave no observable trace in the system’s own behavior.
  • MANAGE 2.3 (on responding to emerging risks): This Task defines the escalation procedure that a sustained or recurring anomaly should trigger where it matches no previously characterized failure mode; it does not cover the intervention and recovery that follow. For those, see for example Practice 4: Define Procedures for Emergency Avoidance Override, Recovery, and Situational Awareness.

Decisions for the Organization:

  • Who watches the monitoring, at what hours, and what happens to an alert raised when no one with authority to act is available?
  • Where continuous monitoring is not affordable for a system, what monitoring interval is accepted, and what risk remains between checks?

References:

  • Guidance NIST SP 800-160v2r1, Developing Cyber-Resilient Systems: A Systems Security Engineering Approach, from NIST. Table D-2 defines the Analytic Monitoring technique as monitoring and analyzing a wide range of properties and behaviors on an ongoing basis and in a coordinated way, with the purpose of detecting potential adverse conditions and revealing their extent, which corresponds to the continuous monitoring this Task establishes. Section C.2 notes that an advanced persistent threat can take advantage of, or make its behavior appear to result from, human error, structural failure or natural disaster. That supports this Task’s request that anomalies consistent with drift be distinguished, where feasible, from those consistent with deliberate interference.
  • Guidance AI Data Security: Best Practices for Securing Data Used to Train & Operate AI Systems, version 1.0, May 2025, joint Cybersecurity Information Sheet from the National Security Agency’s Artificial Intelligence Security Center, CISA, the FBI and partner agencies in Australia, New Zealand and the United Kingdom. Its section on data drift notes that slow, gradual changes in performance more likely indicate drift, and abrupt, dramatic changes more likely indicate an attempt to compromise the model. This is one heuristic for the distinction this Task asks for.
