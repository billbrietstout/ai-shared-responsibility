Implementation 4.1.1: Ensure that SI Systems Can Be Reliably Overridden

Ensure that technical processes for intervening in the AI system’s operation are reliably implemented at appropriate points. Intervention mechanisms should not depend on the SI system’s cooperation to take effect. Test them at commissioning and after significant changes, rather than inferring reliability from the presence of a mechanism. For agents, these tests should include whether the agent continues a blocked action through another tool or delegated agent, or by starting a replica of itself. This Implementation is likely to align with Implementation 3.2.1: Identify SI Output Intercept Points. Examples of override mechanisms include reverting the SI-enabled function to traditional automation or to manual operation and, for agents, revoking the credentials through which the agent acts. Reverting is available only where the organization has kept the traditional automation or manual capability in working order, and it carries its own considerations, such as reduced capacity and manual skills that have eroded (see Task 3.6 and Practice 11). Each mechanism should leave the process in a defined state (Implementation 3.2.3: Specify Fail-Safe States and Fallback Behavior), and its effect can be confirmed in the exercises under Implementation 4.1.3: Regularly Practice and Evaluate Intervention Processes. Where stopping or overriding the SI system could leave it in an insecure state, define the security actions that accompany the stop, as described in Implementation 3.2.3: Specify Fail-Safe States and Fallback Behavior.

Decisions for the Organization:

  • Which override mechanism applies to each SI-enabled function, and what defined state does each leave the process in?

References:

  • Guidance Principles for the Secure Integration of Artificial Intelligence in Operational Technology, December 2025, joint guidance from nine national cybersecurity agencies across seven countries, led by the United States Cybersecurity and Infrastructure Security Agency. Section 2.4, Evaluate Challenges in AI-OT System Integration, asks critical infrastructure owners and operators to prioritize their control over critical functions that SI systems integrate with, and to provide failsafe mechanisms that revert any SI-enabled process to traditional automation or manual operation. Those are override points of the kind this Implementation asks to be reliably implemented.
  • Guidance NIST SP 800-53r5, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement AC-3(10), Audited Override of Access Control Mechanisms, provides an audited override of automated access control under organization-defined conditions by organization-defined roles, for situations such as a threat to human life, which parallels the break-glass model in Task 4.1, including the restriction to authorized roles, and adds an audit record of each use.
  • Guidance NIST SP 800-190, Application Container Security Guide, from NIST. Section 2.3.3 describes the orchestrator as the component that deploys images into containers and manages the running containers, with hosts running and stopping them as the orchestrator directs. Section 4.3 sets the countermeasures that govern it: a least privilege access model, tightly controlled cluster-wide administrative accounts, and node trust. For a containerized AI deployment the orchestrator is one of the appropriate points at which an intervention is implemented, and Section 4.3 is what decides who can exercise it.
  • Guidance OWASP Top 10 for Agentic Applications, Version 2026, December 2025, from the Agentic Security Initiative of the OWASP Gen AI Security Project, a volunteer community project of the Open Worldwide Application Security Project. ASI10, Rogue Agents, includes among its mitigations rapid containment mechanisms such as kill-switches and credential revocation to disable rogue agents, and quarantine of suspicious agents for forensic review, which bears on override points for agentic deployments.
