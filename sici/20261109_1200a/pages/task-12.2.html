Task 12.2: Implement Multi-Layered Validation of Machine-Authored Logic

Checking generated logic in more than one way helps an organization catch errors that a single check would miss, including errors that read as correct. Deploy a hybrid verification strategy that subjects AI-generated outputs to both deterministic automated testing and expert human scrutiny. By checking artifacts against formal specifications and tacit domain knowledge, this task helps ensure that machine-generated instructions remain within safe operational boundaries and are free from ‘plausible hallucinations’. Tests written by the SI system that generated the artifact can share its misreading of a requirement, and they should be reviewed independently before they count as a layer of validation. Reviewers should have the specification, hazard analysis and generation prompt in front of them, not only the artifact and any explanation the generating SI system offers, and should record what they checked as well as their decision. Where SI raises the volume of changes, review effort should scale with it. A reject rate that falls toward zero as volume rises is worth investigating rather than taking as evidence of quality.

Main Trustworthiness Contributions:

  • Valid: Contributes checking of each generated artifact against codified technical standards and the unwritten operating norms of the specific facility, with expert red-team review of safety-critical procedures for plausible errors and omitted warnings. This Task does not cover defining the requirements the artifact is checked against, which Implementation 1.4.4: Requirements for SI-Generated Code, Configurations, Procedures, and Other Logic sets out.
  • Safe: Contributes independent deterministic verifiers, such as static code analyzers and schema validators, that every executable generated artifact passes through against hard-coded safety constraints, with meta-safeguards where the verifiers are themselves written with AI assistance. This Task does not cover constraining what a deployed artifact does at run time, which Task 3.2: Implement Independent Guardrails for SI Outputs addresses.

Trustworthiness Side Effects to Consider:

  • Bias Managed: Expert review of a fluent, plausible artifact is where automation bias acts most readily, and a reviewer who accepts without examining adds a signature rather than a check. Implementation 3.2.5: Artifact Verification conditions review on authority to reject and capacity to examine, and Task 9.2: Deliver Specialized Training on Human-SI Interaction and Automation Bias trains personnel not to treat a plausible rationale as evidence of correctness.
  • Secure: Layered validation adds time before a generated fix can enter service, including a fix for a security vulnerability. Where an organization provides an expedited path for urgent changes, the full review can follow afterward, with the known-good version under Implementation 12.3.2: Version Control and Rollback Procedures held ready.

Related AI RMF Subcategories Include:

  • MEASURE 2.6 (on measuring safety): This Task covers review of generated code, configurations and procedures for safety before use, through deterministic verifiers and expert red-team review; it does not cover evaluating the generating AI system itself under edge-case and stress conditions. For that, see for example Task 2.3: Establish Protocols for and Regularly Perform Systematic and Achievable Testing, Evaluation, Validation, and Verification (TEVV).
  • MAP 4.2 (on establishing risk controls for AI system components): This Task covers layered pre-deployment controls on AI-generated artifacts, combining automated verification with expert scrutiny; it does not cover controls on an AI system’s runtime outputs at the process boundary. For that, see for example Task 3.2: Implement Independent Guardrails for SI Outputs.

Decisions for the Organization:

  • Is there an expedited path for urgent generated fixes, and what review follows it? (see the Secure effect in Task 12.2: Implement Multi-Layered Validation of Machine-Authored Logic)
  • How much reviewer time and expertise does each risk tier call for, who provides it, and what happens to generation when that capacity is not available?

References:

  • Guidance NIST AI 600-1, Artificial Intelligence Risk Management Framework: Generative Artificial Intelligence Profile, July 2024, from NIST. Suggested action MS-2.6-004, under MEASURE 2.6, asks that generative AI outputs be reviewed for validity and safety, including review of generated code to assess risks from unreliable downstream decision-making. Section 2.2, Confabulation, explains why plausible but wrong output is expected from how generative models work and notes that it may be especially important to monitor in consequential decision making, which is the failure the deterministic and expert layers of this Task are meant to catch.
