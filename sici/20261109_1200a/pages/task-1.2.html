Task 1.2: Create Quantitative Baselines for Existing Systems in Both Normal and Challenging Conditions

Measuring how the existing process performs, in hard conditions as well as normal ones, lets the organization tell whether an SI system is an improvement, and where it may be more brittle. Establish quantitative performance baselines for current legacy or manual processes to provide a comparative metric for evaluating SI system effectiveness. These baselines capture performance under both normal and stressed operating conditions, enabling technical managers to identify specific risks and measure improvements associated with the adoption of SI. This Task differs from Implementation 1.1.1: Operational Baseline Review by focusing on minimum performance under challenging conditions to help ensure that performance gains do not result in increased brittleness.

Record the uncertainty of each baseline and the stressed conditions for which there is too little data to set one, along with any known gaps or reporting bias in the historical records it draws on. What can be claimed about the SI system’s relative performance under those conditions is limited in the same way. Where the measured baseline falls short of a requirement identified in Task 1.1: Identify Current Requirements, record the shortfall, so that a decision to require more of the SI system than the existing process achieves is made knowingly.

Main Trustworthiness Contributions:

  • Valid: Contributes the measured “before” that a claimed improvement is checked against (Implementation 1.2.1: Establish Manual or Legacy Process Performance and Safety Baselines), which is what lets a conclusion that an SI system is not the right means here rest on evidence. This Task does not cover benefits for which the legacy process offers no counterpart, such as a capability that did not previously exist.
  • Robust: Contributes the comparison point beyond expected conditions: the manual or legacy process measured under stress and edge cases (Implementation 1.2.2: Develop High-Fidelity Operational Baselines Including Edge-Case Performance Under Stress), so brittleness introduced by an SI system appears as a like-for-like difference rather than as a surprise in service. This Task does not cover characterizing the SI system’s own behavior in those conditions. For that, see Task 2.3: Establish Protocols for and Regularly Perform Systematic and Achievable Testing, Evaluation, Validation, and Verification (TEVV).

Trustworthiness Side Effects to Consider:

  • Privacy-Enhanced: Baselining a manual process measures the people who carry it out, and records kept at that level describe how individuals work. Aggregating the measures, and agreeing their use with the workforce, can limit this. Governing those records belongs with the organization’s existing workforce monitoring and privacy practice.
  • Fair: A baseline drawn from historical service records carries any unevenness in past service across locations or populations. An SI system that matches such a baseline can reproduce that unevenness while appearing to perform as well as the process it supports or replaces. Comparing performance for the groups served, as well as in aggregate, can show this.
  • Secure: A stressed-condition baseline records the conditions under which the existing process, and the people running it, perform worst, such as a plant upset or an alarm flood (Implementation 1.2.2: Develop High-Fidelity Operational Baselines Including Edge-Case Performance Under Stress). An attacker could use it to time an attack for when operators are least able to respond. Protecting the baseline records is a matter for the organization’s existing information classification and handling practice.

Trustworthiness Tensions to Balance:

  • Accurate versus Robust: Where only normal operation is baselined, a candidate that improves the average compares well. Where the stressed baseline is measured as well, a candidate that is sharper on average and weaker at the edges shows the trade, and the two comparisons can point to different decisions. One way to balance this is to set an acceptance bar on the stressed baseline as well as the normal one, so that an average gain does not by itself carry the decision. Others include accepting the trade with the brittleness recorded as a known limitation, or keeping the legacy path available for the conditions in which it performs better, with the resources for that allocated under Task 11.1: Identify and Prioritize SI-Dependent Essential Functions.

Related AI RMF Subcategories Include:

  • MAP 3.1 (on understanding benefits): This Task measures how the manual or legacy process actually performs before anything is deployed, so a claimed benefit can be checked against a documented “before” rather than an estimate; it does not cover examining benefits for which the legacy process offers no counterpart, such as a capability that did not previously exist.
  • MAP 3.2 (on understanding costs): This Task baselines performance under stressed and edge-case conditions as well as normal ones, so that brittleness introduced by the SI system shows up as a like-for-like comparison rather than as a surprise in service; it does not cover relating the resulting costs to a level of risk the organization is willing to carry. For that, see for example Implementation 3.1.3: Define Acceptable Risk Thresholds and Associated Control Responses.
  • MANAGE 2.1 (on allocating resources): This Task documents how the viable non-AI alternative performs, including under stress, so that keeping that alternative becomes a costed choice rather than an assumption; it does not cover allocating the resources needed to keep it available. For that, see for example Task 11.1: Identify and Prioritize SI-Dependent Essential Functions.

Decisions for the Organization:

  • Is acceptance judged on the normal baseline, the stressed baseline, or both? (see the Accurate versus Robust tension in Task 1.2: Create Quantitative Baselines for Existing Systems in Both Normal and Challenging Conditions)
  • Where a candidate is weaker at the edges, is the brittleness accepted and recorded, or is the legacy path kept for those conditions?
  • Who collects the baseline measures, over what period, and whose time and budget does it draw on?
