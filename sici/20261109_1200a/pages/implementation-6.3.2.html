Implementation 6.3.2: Implement Egress Monitoring and Isolated, Access-Restricted Enclaves for SI Training and Telemetry

Egress monitoring and restricted paths help an organization detect unauthorized data transfers and limit what can leave if an SI system or vendor connection is compromised. Monitor the egress points cataloged in Implementation 6.3.1: Catalog Data Egress Points and Third-Party Processing Destinations for unexpected volume or destination changes, and route sensitive data used for AI training or telemetry through isolated, access-restricted environments rather than general-purpose network paths. Flows to a destination that is not in the catalog warrant attention, as well as changes at cataloged points. For data leaving OT networks, push-based or brokered transfer, using a unidirectional gateway where feasible, can help keep the enclave from becoming a persistent inbound path into control systems. Suppliers then receive a reviewed extract rather than live access to operational systems. Flow logs and access logs for SI endpoints that attribute egress to an asset and identity, together with data loss prevention inspection of prompts and outputs, can support this monitoring. Where agents choose at runtime which tools and external services to call, a catalog prepared in advance cannot list every destination; record at each tool call the classification of the data passed, its destination, and a hash of the payload, so that the path the data took can be reconstructed (Implementation 8.1.5: Multi-Agent Cascade Reconstruction Capabilities).

Decisions for the Organization:

  • Where is one-way or brokered transfer used for data leaving OT networks?

References:

  • Guidance NIST SP 800-53r5, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement SC-7(10), Prevent Exfiltration, addresses both intentional and unintentional exfiltration, and its techniques include traffic profile analysis to detect deviations from the expected volume and types of traffic, which is the monitoring of AI data egress points for unexpected volume or destination changes asked for here.
  • Guidance Principles for the Secure Integration of Artificial Intelligence in Operational Technology, December 2025, joint guidance from nine national cybersecurity agencies across seven countries, led by CISA. Section 3.2, Integrating AI Into Existing Security and Cybersecurity Frameworks, lists under robust security controls collecting flow logs and access logs for AI endpoints, tracking data egress by asset and identity, and integrating with data loss prevention for prompt and output inspection. This bears on how the egress monitoring in this Implementation can be instrumented.
  • Guidance NIST SP 800-82r3, Guide to Operational Technology (OT) Security, September 2023, from NIST. Section 5.2.3.1, Network Architecture, describes a unidirectional gateway or data diode as an alternative to firewalls that permits authorized communication in only one direction. Appendix E.1.2 gives its common use at the boundary between operational and enterprise networks, letting traffic leave the operational network but not enter. This bears on how data reaches the enclave this Implementation describes from OT networks.
