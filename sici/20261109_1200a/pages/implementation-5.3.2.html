Implementation 5.3.2: Task-Bounded and Revocable Agent Authority

Authority that expires with the task, and can be revoked quickly, helps limit how long a compromised or malfunctioning SI agent can keep acting. Bound an AI agent’s authority to a specific task, operational mode, or time window rather than granting permanent standing privileges. When an AI system delegates execution to downstream tools or sub-agents, authority should be explicitly scoped per task. Authority delegated to an SI system should not exceed that of the person or organization on whose behalf it acts. If a downstream agent or tool possesses specialized privileges as described in Implementation 5.3.3: Separate Privilege via Encapsulated Downstream Agents and Tools, strict, deterministic validation and hard-coded operational boundaries should be enforced to help prevent execution beyond its intended design. Systems should support rapid authority revocation and automatic expiration. Set the credential lifetime, the rotation interval, and the time within which a revocation takes effect for each SI entity, and confirm them by test rather than by configuration alone. In partitioned or remote environments where real-time authority checks may fail, systems should revert to pre-engineered, local fallback behaviors (Implementation 3.2.3: Specify Fail-Safe States and Fallback Behavior) rather than maintaining unverified standing authority. Revocation should reach the authority that the agent has passed to downstream tools and sub-agents, including tokens they have cached, and should take effect where access is enforced rather than depending on the agent to stop. For example, in OT an agent’s authority over an asset can be tied to the permit-to-work or maintenance window that authorizes the work, so that the authority lapses when the permit closes. This applies an existing permit-to-work process to the SI agent rather than creating a new one.

Decisions for the Organization:

  • What credential lifetime, rotation interval and revocation time are set for each SI entity?

References:

  • Guidance NIST SP 800-53 Rev. 5, Release 5.2.0, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement IA-13(3), Token Management, added to the catalog after the 2020 Rev. 5 publication and included in Release 5.2.0, calls for assertions and access tokens to be generated, issued, refreshed, revoked, time-restricted and audience-restricted under an organization-defined policy, and its discussion stresses restricting a token to a specific audience and limiting its validity lifetime. Short-lived, audience-restricted tokens are one way to bound an agent’s authority to a task or time window with automatic expiration.
  • Guidance NIST SP 800-160v2r1, Developing Cyber-Resilient Systems: A Systems Security Engineering Approach, from NIST. Table D-4 describes the Dynamic Privileges approach to Privilege Restriction as elevating or decreasing the privileges of a user, process or service based on transient or contextual factors. Its examples include time-based adjustments tied to the status of mission or business tasks, dynamic account provisioning and dynamic revocation of access authorizations, which corresponds to the task-bounded, expiring authority this Implementation calls for. Section D.5.2.2 adds that the criticality of a resource can change dynamically, so that a resource vital to one phase of mission processing can become unimportant after that phase.
  • Guidance Agentic Identity and Access Management, Workstream 4: Secure Design Patterns for Agentic Systems, version 1.0, 20 March 2026, from the Coalition for Secure AI, an OASIS Open Project. Section 3.4 asks that, when a delegation is revoked at any point, downstream delegations be invalidated through centralized revocation services or event-driven propagation. Its Appendix D asks for short-lived, tightly scoped delegation tokens and runtime components that stop accepting revoked tokens immediately, and names RFC 8693 (Token Exchange) and RFC 7009 (Token Revocation). This bears on revocation reaching delegated authority.
