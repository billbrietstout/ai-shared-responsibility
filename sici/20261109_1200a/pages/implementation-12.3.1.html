Implementation 12.3.1: Isolated Execution Testing (Sandboxing)

Testing generated code and configurations away from production helps an organization see what they do before they can affect live equipment. Where feasible, test AI-generated configurations or code in a digital twin or isolated simulation environment before deployment to production systems. Keep the test environment separate from production, sharing as few networks, credentials, and services with it as practical and recording any that are shared, so that generated code under test cannot reach production systems or networks. Run generated code under test without elevated privileges. Where no digital twin or simulation exists, a replicated or virtualized system can serve as the test environment. Results from a digital twin apply only to the conditions that it reproduces, and Implementation 2.3.3: Use Digital Twins to Regularly Test SI System Behavior discusses those limits. Testing can exercise startup, shutdown and trip sequences, injected faults such as a failed sensor or lost communications, and values at and beyond range limits, comparing the results with the requirements or the cause-and-effect matrix.

Decisions for the Organization:

  • Where no digital twin or simulation exists, what serves as the test environment?

References:

  • Guidance NIST SP 800-53r5, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement CM-4(1), Separate Test Environments, analyzes changes in a physically or logically separate test environment before implementation in the operational environment, looking for security and privacy impacts due to flaws, weaknesses, incompatibility or intentional malice, which supports testing AI-generated configurations and code in a digital twin or isolated simulation before deployment.
  • Guidance NIST SP 800-82r3, Guide to Operational Technology (OT) Security, September 2023, from NIST. Section 5.2.5.2, Patching, recommends testing patches on a sandbox system before they are deployed into production. Appendix F.7.4, in the OT discussion of CA-8, Penetration Testing, gives a replicated, virtualized or simulated system as a compensating control where testing on production OT is not appropriate. Both carry over to testing SI-generated configurations and code for OT.
  • Guidance OWASP Top 10 for Agentic Applications, Version 2026, December 2025, from the Agentic Security Initiative of the OWASP Gen AI Security Project, a volunteer community project of the Open Worldwide Application Security Project. Entry ASI05, Unexpected Code Execution, asks that agent-generated code not go directly to production, that it run in sandboxed containers with strict limits including network access and never as root, and that code generation be separated from execution with validation gates.
