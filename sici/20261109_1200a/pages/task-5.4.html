Task 5.4: Implement Continuous Monitoring of SI Entities Against Access and Action Boundaries and Expectations

Monitoring helps an organization notice an SI entity that authenticates correctly and then acts outside its role, whether through compromise or malfunction. Organizations with established monitoring of user and service accounts can extend it to SI entities. Continuously monitor AI entity actions against defined access boundaries to detect out of scope actions, unauthorized access attempts, and privilege escalations.

Main Trustworthiness Contributions:

  • Secure: Contributes detection of the entity that authenticates correctly and then acts beyond its boundary, through monitoring against defined access boundaries and against an established pattern of access, whether the cause is compromise or a malfunction such as a runaway loop. This Task does not cover setting the boundaries a deviation is measured against, which Task 5.2 and Task 5.3 set.
  • Transparent: Contributes a record of AI entity authentication and access events, including the attempts that failed, together with a defined cadence at which a person examines it. This Task does not cover capturing the inputs, prompts and model context needed to reconstruct why an action was taken, which Practice 10: Implement Multi-Tiered SI System Logging and Audit Capabilities covers.

Trustworthiness Side Effects to Consider:

  • Safe: Detection at machine speed produces notifications, and an entity population that is partly ephemeral produces deviations from an established pattern as a matter of course. Where those notifications reach the same people who watch operations, Task 4.4: Attention Governance and Alert/Alarm Flood Mitigation treats notification volume as a designed quantity rather than a byproduct.
  • Secure: The access log and the behavioral baseline in Implementation 5.4.2: Deploy Real-Time Behavioral Anomaly Detection for SI Agent Activity show what each SI entity normally does, which identities hold which access, and what activity raises an alert. An attacker who knows the baseline could keep a compromised entity’s activity within it. Protecting these records is a matter for the organization’s existing information classification and handling practice, with Task 10.2: Establish Data Integrity and Tamper-Evidence Controls for Telemetry and Logging covering the integrity of the logs themselves.

Trustworthiness Tensions to Balance:

  • Secure versus Safe: Where an SI entity’s actions can be paused without consequence for the process, suspending it automatically on detection limits misuse at little cost. Where it is part-way through operating actions, or the deviation coincides with an abnormal operating condition in which legitimate behavior also departs from its usual pattern, automatic suspension can itself leave the process in a hazardous state. One way to balance this is to reserve automatic suspension for high-confidence detections and to define with operations what suspension means for each SI entity, as Implementation 3.2.3: Specify Fail-Safe States and Fallback Behavior does for refused actions. Others include narrowing the entity’s authority rather than suspending it, or routing detections made during a declared abnormal condition to a person.

Related AI RMF Subcategories Include:

  • MEASURE 2.4 (on monitoring deployed AI systems): This Task monitors AI entity actions in production against defined access boundaries, and alerts in real time where a later log review would arrive too late; it does not cover monitoring the quality of what the AI produces. For that, see for example Task 3.4: Monitor for Anomalous SI Behavior.
  • MEASURE 2.7 (on measuring security and resiliency): This Task covers continuous runtime evidence of security posture, in the form of authentication, access and privilege-escalation events; it does not cover evaluating the resilience that MEASURE 2.7 also names. For that, see for example Practice 2: Define SI Robustness, Resilience, and Quality of Service Expectations.

Decisions for the Organization:

  • Which detections, if any, trigger automatic suspension, and what does suspension mean for each SI entity? (see the Secure versus Safe tension)
  • Which team is resourced to monitor SI entity activity, and does it have the time, access, and authority to act on what it finds?

References:

  • Guidance MITRE ATLAS, from MITRE, a United States not-for-profit corporation that operates federally funded research and development centers. A public catalog of adversary tactics and techniques observed against AI systems, used here to categorize runtime telemetry anomalies and to guide post-incident triage.
  • Guidance NIST SP 800-53r5, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control SI-4, System Monitoring, monitors the system to detect attacks, indicators of potential attacks, and unauthorized local, network and remote connections, and to identify unauthorized use. Control enhancement SI-4(13), Analyze Traffic and Event Patterns, develops profiles of common traffic and event patterns and uses them to tune monitoring. Its discussion says that such profiles can help reduce false positives and false negatives. Applied to SI entities, these are the monitoring against boundaries and against an established pattern that this Task describes.
