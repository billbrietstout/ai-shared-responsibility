Task 9.1: Perform Role-Based SI Risk Competency Mapping

Identify specific AI-related knowledge and skills required for different organizational roles, from executive level to front-line operations. This Task helps ensure that training is targeted to the specific risks encountered in each role and provides those responsible for mission continuity with relevant, actionable information and practice. Organizations that already analyze training needs by role, for cybersecurity or operational training, can build on that analysis.

Main Trustworthiness Contributions:

  • Accountable: Contributes a mapping from each role that uses, supervises or can override an AI system to the AI literacy and risk awareness that role requires, distinguishing what a front-line operator needs from what an executive needs, so that responsibility assigned to a role comes with defined competence. This Task does not cover assigning the responsibilities or decision authority themselves, which Implementation 3.9.1 and Implementation 3.9.2 set out.
  • Accurate: Contributes better source records for the AI system: Implementation 9.1.3: Include Data-Originating Roles in Competency Mapping extends the mapping to the people who create the data the AI system consumes, covering which fields are used downstream and what makes an entry unusable, so that inputs agree more closely with the conditions they record. This Task does not cover assessing the data that results, which Implementation 7.2.1 and Implementation 7.2.3 cover.

Trustworthiness Side Effects to Consider:

  • Secure: A competency matrix that records each person’s assessed level against what their role requires (Implementation 9.1.2: Develop a Comprehensive SI Risk Competency Matrix and Personalized Learning Paths) shows who can override which SI system and where skills are thin. An attacker could use it to target a person or shift less likely to catch a manipulated output. Protecting it is a matter for the organization’s existing information classification and handling practice.

Related AI RMF Subcategories Include:

  • GOVERN 2.2 (on training for AI risk management): This Task covers the role-by-role determination of what AI risk training each role needs, extended to roles that only create the data an AI system consumes; it does not cover delivering that training. For training of operational personnel, see Task 9.2: Deliver Specialized Training on Human-SI Interaction and Automation Bias.
  • GOVERN 2.1 (on establishing roles and responsibilities): This Task covers a definition of the AI-related knowledge each role needs in order to discharge its responsibilities; it does not cover documenting the roles, responsibilities and escalation lines themselves. For those, see for example Implementation 3.9.1 and Implementation 3.9.3.

Decisions for the Organization:

  • Which roles are included in the mapping, and how far along the data chain does it extend?

References:

  • Guidance NIST SP 800-50r1, Building a Cybersecurity and Privacy Learning Program, September 2024, from NIST. Section 2.6 asks that the complexity of learning material be commensurate with the role of the person being trained. Section 3.1.2 sets out an analysis phase that identifies learning needs from work role activities and tasks, matches them to each audience, assesses current knowledge and skill, and determines the gaps. This is the analysis this Task applies to SI risk competence by role.

Implementations of this Task

  • Implementation 9.1.1: Identify Required SI Literacy and Risk Awareness Levels for Existing Operational Roles
  • Implementation 9.1.2: Develop a Comprehensive SI Risk Competency Matrix and Personalized Learning Paths
  • Implementation 9.1.3: Include Data-Originating Roles in Competency Mapping
