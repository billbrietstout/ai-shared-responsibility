Implementation 13.2.3: Reclaim Resources, Not Only Permissions

Identify and reclaim the compute and storage resources associated with the AI system, including containers, sandboxes, scratch storage and cached data. The same applies to network and naming resources registered for the system, such as DNS names, network addresses, endpoints, message queues and storage bucket names. A name released while other systems still trust it may be registered by another party and used to impersonate the retired system. Firewall rules and other boundary permissions opened for the system, for example between IT and OT zones, should also be removed. Resources and boundary permissions of this kind are distinct from the permissions revoked under Implementation 13.2.1: Revoke Credentials and Disable Triggers, and Confirm the Result and are often missed because the retirement record is organized around authorizations. An orphaned execution environment may hold a mounted credential that survives the revocation of everything else, keep running work that nobody is any longer watching, or retain cached data, including personal data, that outlives the retention decisions made for the system’s main stores. What happens to the model, training pipeline and datasets themselves is addressed in Implementation 7.6.2: Secure Archiving and Destruction of Model and Other SI Artifacts.

Decisions for the Organization:

  • Which network names, addresses and endpoints are released, and which are held for a period so that another party cannot register them?

References:

  • Guidance NIST SP 800-88r2, Guidelines for Media Sanitization, from NIST. Section 3.1 sets out the Clear, Purge and Destroy methods and the basis for choosing between them, which is the decision to be made for each storage resource associated with a retired AI system rather than one choice applied to all of them.
