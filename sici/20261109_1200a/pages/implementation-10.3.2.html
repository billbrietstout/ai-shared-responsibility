Implementation 10.3.2: Implement Automated Trend Analysis and Dashboarding for Continuous Audit Oversight

Because an SI system can drift by small amounts that add up, a long view helps an organization notice change that no single review would show. Build automated dashboards that surface performance trends from the logs over time, reducing reliance on manual review alone and giving the roles the organization assigns to oversight continuous visibility into slow-developing issues between formal audit cycles. Record which roles receive them. These dashboards show how often controls block actions and where records are incomplete. An attacker who can see them could learn which attempts are caught and where an action is least likely to be reconstructed. Limit access to the roles that receive them, under the organization’s existing information classification and handling practice. Examples of trends to surface include how often the guardrails of Task 3.2: Implement Independent Guardrails for SI Outputs and the authorization checks of Implementation 5.2.2: Action-Level, Context-Aware Authorization Policies block or modify SI actions, so that a control that is working is not mistaken for an absence of risk. Other examples are how often an action takes effect without a matching authorization record, and how often a decision can be reconstructed from its logs. Where it can later be established whether consequential outputs were correct, for example from reversed transactions, corrected dispatches or overridden recommendations, consider also tracking the rate of incorrect consequential outputs, weighted by their consequence, since an SI system can remain within the drift thresholds set under Implementation 3.3.2: Establish Maximum Drift Thresholds and still produce wrong outputs that are acted on. Where outcomes can be broken down by population, site or operating condition, trend each group as well as the overall figure, since an average can mask degradation in a subgroup.

Decisions for the Organization:

  • Which roles receive the dashboards?
  • Which trends are tracked, and is the rate of incorrect consequential outputs among them?

References:

  • Guidance NIST SP 800-137, Information Security Continuous Monitoring (ISCM) for Federal Information Systems and Organizations, from NIST. Section 3.4.2, Report on Security Control Assessments, describes reports whose content and frequency vary with the recipient, for example from an annual summary for the risk executive to dashboards of network activity updated every minute with summary metrics updated hourly or daily, and suggests more frequent reporting for controls that are more volatile or have shown weaknesses. Although written for federal information systems, it is a model for matching the dashboards this Implementation calls for to the people who act on them.
  • Research Dolin, P., Li, W., Dasarathy, G., and Berisha, V., Statistically Valid Post-Deployment Monitoring Should Be Standard for AI-Based Digital Health, NeurIPS 2025 Position Paper Track, arXiv:2506.05701, from Arizona State University. Section 1 notes that post-deployment evaluation is often based on average performance metrics checked manually and sporadically, and that average metrics can mask degradation in specific subgroups. The Abstract frames detecting changes in the data and detecting performance degradation as distinct statistical tests. It addresses predictive clinical models and excludes generative ones. It bears on what the trend analysis in this Implementation tracks.
