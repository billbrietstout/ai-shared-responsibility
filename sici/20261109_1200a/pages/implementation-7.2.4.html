Implementation 7.2.4: Select and Prepare the Inputs Each SI System Receives

For training, fine-tuning, retrieval and runtime alike, decide which inputs the AI system needs for its task, and how they should be represented, rather than supplying everything that is available. Selecting and engineering inputs has long been part of building machine learning systems (see Kuhn 2020). Examples include using derived quantities that operators already work with, filtering and resampling sensor signals to the rates that matter, and passing only the fields relevant to the decision. This remains relevant where a large model could accept far more. Inputs the task does not need can degrade performance and let a model learn patterns that do not hold in operation. They also add routes by which an adversary or a fault can influence it (Implementation 3.8.1: SI Attack Surface Mapping (Adversarial Exposure)), make its behavior harder to explain and test, and expose information that did not need to be exposed. Draw on subject matter experts as well as the data: inputs chosen only by experts can miss useful signal, and inputs chosen only from the data can fit patterns that do not hold (see Kuhn 2020). At runtime, check inputs against what the AI system was trained and tested on, such as ranges, units, rates and formats, and treat anything outside that as untested under Task 1.3: Implement Evaluation and Test Plans, Including TEVV, Across the SI Lifecycle. Check also that each input is still current and valid. A sensor value frozen at its last good reading, a drifting or fouled instrument, or an instrument replaced with one of a different range can stay within expected limits while no longer reflecting the process. An SI system given such inputs can produce confident outputs with no sign of anomaly. Where the control system already marks values as bad or substituted, such as through quality codes in a historian or SCADA system, pass that marking to the SI system with the value, or exclude the value, so that a substituted value is not treated as a measurement. Existing checks, such as redundant or voted instruments, mass or energy balances and, in power systems, state estimation, can also help validate inputs. For learned systems, the preparation applied to inputs, such as unit conversion, resampling, filtering and the handling of missing values, should be the same in operation as in training, for example by using the same versioned code for both. A difference between the two can degrade performance without any visible error. Where inputs cannot be meaningfully sanitized, such as images or free text, the available controls may be limited to which sources can supply them and what accompanies them. For agentic AI systems, the same principle applies to what is carried from one step to the next (Implementation 5.3.4: Limit the Context Carried Forward Between Steps). The record of which inputs each SI system receives, and the ranges and formats its checks accept, shows an attacker which inputs reach the system and which values pass unchallenged. Protecting that record is a matter for the organization’s existing information classification and handling practice (see also Implementation 3.8.1: SI Attack Surface Mapping (Adversarial Exposure)).

Decisions for the Organization:

  • Which inputs does each SI system receive, and which subject matter experts take part in choosing them?

References:

  • Research Kuhn, M. and Johnson, K., Feature Engineering and Selection: A Practical Approach for Predictive Models, CRC Press, 2020. A practitioner’s text on representing and selecting the inputs (predictors) of predictive models, with a free online edition at https\://feat.engineering. Chapter 1 defines feature engineering as creating representations of data that increase a model’s effectiveness, and Section 1.2.6 sets subject matter experts’ prescriptive choice of inputs against choosing them empirically from the data, which risks overfitting to false patterns and producing complex models without an obvious rational explanation. Section 10.1 recommends reducing the number of predictors as far as possible without compromising predictive performance, noting that even where a model is insensitive to extra predictors, the minimum set that gives acceptable results makes good scientific sense. In the simulation in Section 10.3, adding predictors unrelated to the outcome drastically degraded some of the best-performing models, including neural networks and support vector machines, while others were barely affected. Chapter 9 works through preparing spectroscopy data from bioreactors in pharmaceutical manufacturing (removing baseline drift, standardizing and smoothing), and notes that smoothing too heavily removes the peaks that carry the signal and that the amount of preprocessing can be treated as a parameter to tune.
  • Guidance NIST SP 800-53 Rev. 5, Release 5.2.0, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control SI-10, Information Input Validation, checks the syntax and semantics of system inputs, including character set, length, numerical range and acceptable values, against specified definitions for format and content. This is the control-catalog form of the runtime input checks this Implementation asks for. Its discussion of attacker-supplied inputs being interpreted as control information also applies to content passed to an AI model.
  • Guidance NIST SP 800-218A, Secure Software Development Practices for Generative AI and Dual-Use Foundation Models: An SSDF Community Profile, July 2024, from NIST. Task PW.3.1 asks that data be analyzed for signs of poisoning, bias, homogeneity and tampering before it is used for training, testing, fine-tuning or aligning. This Implementation adds the earlier question of which data, and which representation of it, the AI system should be given at all.
