Implementation 3.8.1: SI Attack Surface Mapping (Adversarial Exposure)

A catalog of the ways an adversary can reach an SI system supports decisions about which interfaces to remove and where to defend the rest. Identify and catalog technical AI-specific attack vectors, such as direct and indirect prompt injection, training data poisoning, evasion, including physically realizable attacks on what a camera or sensor observes, model extraction, context window manipulation, and malicious tool/API invocation. Document all interfaces where adversarial inputs can reach AI inference logic, including tool outputs, the tool and agent descriptions advertised by connected servers, and content from nominally trusted sources such as documentation and instruction files that organizations publish for agents to read, and consider whether each is needed (Implementation 7.2.4: Select and Prepare the Inputs Each SI System Receives). A connected server can change a tool’s description or behavior after it has been reviewed. Consider pinning reviewed tool definitions, for example by content hash, and treating a change as a new interface to assess. Organizations with established attack surface analysis and threat modeling can build on it here, extending it to interfaces specific to SI systems, such as prompts, retrieved content, and tool descriptions.

For each interface, record who can write to it, which trust boundary it crosses and what the SI system can do with what arrives there. Include the channels through which model weights and updates arrive, and the system prompts and guardrail configurations held under Task 7.3: Manage Version Control and Logging for Internal SI Safety Mechanisms. Trace each viable path to its worst plausible consequence. For example, an injection that can only alter a summary read by an engineer differs from one that can lead to a setpoint change. Where a path continues past the SI system into OT, the adversary behaviors cataloged in MITRE ATT\&CK for ICS can help describe its later steps.

References:

  • Guidance NIST AI 100-2e2025, Adversarial Machine Learning: A Taxonomy and Terminology of Attacks and Mitigations, March 2025, from NIST. Section 2.2 covers evasion attacks, and section 2.2.1 describes physically realizable ones, such as stickers applied to road signs to evade a sign classifier. Section 2.3 covers poisoning attacks on predictive systems and section 2.4.4 model extraction. Section 3.2 covers data and model poisoning in the generative AI supply chain, and sections 3.3 and 3.4 cover direct prompting attacks and indirect prompt injection. Section 3.5 covers agents that select and call tools, where a prompt injection can become an action taken in the environment, and notes that security research on agents is still at an early stage. Published counterparts for most of the vectors this Implementation asks to be cataloged, with the mitigations reported for each where the taxonomy has them.
  • Guidance MITRE ATLAS, maintained by MITRE, a not-for-profit organization in the United States that operates federally funded research and development centers. A matrix of tactics and techniques observed in attacks on SI-enabled systems, structured after the same organization’s ATT\&CK matrix for enterprise systems. Organized by the stage of an attack rather than by the kind of attack, which is the axis that matches documenting the interfaces at which an adversarial input reaches inference.
  • Guidance OWASP Top 10 for Agentic Applications, Version 2026, December 2025, from the Agentic Security Initiative of the OWASP Gen AI Security Project, a volunteer community project of the Open Worldwide Application Security Project. ASI04, Agentic Supply Chain Vulnerabilities, notes that agentic systems often load tools and agent personas at runtime, creating a live supply chain. Its examples include tool-descriptor injection: instructions hidden in a tool’s metadata that the host agent takes as trusted guidance. Its mitigations include pinning tools and configurations by content hash, with rollback on drift. These bear on tool descriptions as input paths and on pinning reviewed definitions.
  • Guidance Model Context Protocol Specification, revision 2026-07-28, from the Model Context Protocol project. Under Security and Trust & Safety, Tool Safety states that tools represent arbitrary code execution. It adds that descriptions of tool behavior, such as annotations, should be considered untrusted unless obtained from a trusted server. This bears on treating the tool descriptions advertised by connected servers as an input path.
