Implementation 7.5.1: Perform Pre-Update Validation and Re-Calibration

Validation before an update is deployed helps an organization find regressions, such as worse performance on one class of input, while they can still be addressed. Validation and re-calibration should be performed before deploying any updates to models, system prompts, databases, and other components of AI systems that affect performance and safety. This should be informed by Practice 1 and Practice 2. Changes to performance should be documented and, where necessary, mitigating controls should be put in place prior to deployment. Validation data can include recent operating conditions and cases drawn from incident and near-miss reports, such as those received under Task 8.6: Establish Non-Punitive Reporting for SI-Related Near-Misses. Record the version of the validation data with the results. For example, a new model for an AI system that summarizes and prioritizes equipment condition reports for maintenance scheduling might have improved accuracy overall.

Pre-update validation might reveal an unacceptably higher false negative rate for specific types of equipment that could not be addressed by re-calibrating thresholds. Mitigating controls can then be put in place, such as having the AI system fall back onto the previous model for reports from these types of equipment. Keep the previous version deployable until the update has been validated in operation, so that a fallback of this kind remains available (see also the comparison in Implementation 7.5.2: Perform Automated “Champion-Challenger” Assessment). Where outputs of the SI system feed thresholds, alarms or confidence-based rules, re-calibration means adjusting those settings so that they again match the updated system’s observed error rates. Some guidance, such as Deploying AI Systems Securely, expects a new model version to be within acceptable limits before it is redeployed. Where no mitigating control adequately addresses a safety-relevant regression, withhold the update unless the role that owns the safety function formally accepts the regression. That role needs the information, time, and authority to judge the regression, and to reject it. Record the outcome and the reason for it. Protect the integrity of any reference or historical dataset used for this comparison. A comparison against reference data that is itself poisoned or otherwise compromised is invalid.

Decisions for the Organization:

  • How long is the previous version kept deployable after an update?
  • Where no mitigating control adequately addresses a safety-relevant regression, is the update withheld?

References:

  • Guidance NIST SP 800-53r5, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement CM-3(2), Testing, Validation, and Documentation of Changes, tests, validates and documents changes before their implementation is finalized. Its discussion notes that testing should not interfere with mission operations, that operational systems may need to be taken offline or replicated before testing, and that compensating controls apply where testing on operational systems is not possible. This is the established control form of the pre-update validation this Implementation asks for.
  • Guidance Deploying AI Systems Securely: Best Practices for Deploying Secure and Resilient AI Systems, Version 1.0, April 2024, from the National Security Agency’s Artificial Intelligence Security Center with CISA, the FBI and partner agencies. Under Update and patch regularly, it asks that a full evaluation be run when a model is updated to a new or different version, so that accuracy, performance and security tests are within acceptable limits before redeployment. This is the pre-update validation this Implementation asks for, stated for SI systems.
  • Guidance Artificial intelligence and machine learning: Supply chain risks and mitigations, 2025, from the Australian Signals Directorate, co-sealed by national cyber security agencies of Canada, Japan, the Republic of Korea, New Zealand, Singapore, the United Kingdom and the United States (the National Security Agency). Under performance testing of machine learning models, it notes that where an existing standard or historical dataset is compared against live results, steps should be taken to protect its integrity, since any comparison would be invalid if that reference data were also poisoned or compromised. This is the pitfall named at the end of this Implementation.
