Implementation 3.1.4: SI-Generated Artifact Driven Impact Analysis

Conduct an assessment of how an error in SI-generated content, code, procedures, or configurations could lead to cascading failures in physical infrastructure. Trace each such artifact from the point where it is generated, through review and deployment, to the equipment or process it governs. Identify the adverse states that an error in it could put that equipment in, including states of systems coupled to it. The dependency mapping in Implementation 3.5.1: Map Direct Functional and Algorithmic Dependencies can help identify those coupled systems. The results can inform how rigorously each artifact is verified under Implementation 3.2.5: Artifact Verification. LLM-generated code can show defect patterns that differ from those of human-written code, such as references to libraries or interfaces that do not exist. An assessment built only around human error modes can miss them.

References:

  • Guidance NIST AI 600-1, Artificial Intelligence Risk Management Framework: Generative Artificial Intelligence Profile, July 2024, from NIST. Suggested action MS-2.6-004, under MEASURE 2.6, asks that generated code be reviewed to assess risks that may arise from unreliable downstream decision-making. It is the generative SI form of the assessment this Implementation asks for before an artifact reaches physical infrastructure.
  • Guidance NIST IR 8179, Criticality Analysis Process Model: Prioritizing Systems and Components, April 2018, from NIST. Sub-process E.3, Review Impact of Operating States, traces the impact of each adverse operating state of a component up to the system and the activity it supports. In the worked example in Appendix D, the group finds that a failure in one part of a software application could cascade across the wider system. This is a structured method for the tracing this Implementation asks for.
  • Research Cotroneo, D., Improta, C., and Liguori, P., Human-Written vs. AI-Generated Code: A Large-Scale Study of Defects, Vulnerabilities, and Complexity, preprint arXiv:2508.21634v1, August 2025, from the University of Naples Federico II. Comparing over 500,000 Python and Java samples, it finds distinct defect profiles for AI-generated and human-written code, with more high-risk security vulnerabilities in the AI-generated code. Section I notes that existing defect frameworks assume human cognition and error modes, while SI-generated code can include hallucinated libraries or APIs. This bears on which errors the assessment here looks for.
