Implementation 3.2.1: Identify SI Output Intercept Points

Choosing where monitoring and controls act on significant SI outputs helps an organization check, and if needed stop, an output before it takes effect, including when the system acts faster than a person can review. For AI decision points deemed to be significant (defined in Implementation 3.1.1: Identify SI System Decision Points and Potential Outcomes of SI System Errors), identify operational intercept points where monitoring and controls can be enforced across one or more locations in the system architecture. These intercept points may indicate where a “guarded proxy” architecture is advisable (see Implementation 5.3.3: Separate Privilege via Encapsulated Downstream Agents and Tools): remove direct asset access from the AI agent or system and route execution requests through an encapsulated downstream tool equipped with independent deterministic constraints (Implementation 3.2.2: Define and Independently Enforce Deterministic Operational Constraints). Where the organization already groups its OT assets into zones with defined conduits between them, as in the ISA/IEC 62443 series, the conduits into zones that hold control or safety assets can be candidate intercept points.

For example, an AI flow-rate optimizer should not hold direct control-bus credentials; it should submit recommendations to a dedicated setpoint broker that independently verifies range, rate-of-change, and safety interlock rules before writing changes to physical hardware. In this scenario, intercept points exist at multiple operational layers, including the setpoint interface, the local controller, and existing emergency shutoff mechanisms. Emergency shutoff mechanisms appear here as a further layer that acts on the process. A safety wrapper may act through them, for example by triggering an emergency shutoff where that is practical and permitted, but should not sit on their path (Implementation 3.2.2: Define and Independently Enforce Deterministic Operational Constraints).

Decisions for the Organization:

  • Which intercept points are used for each significant decision point?

References:

  • Guidance NIST SP 800-82r3, Guide to Operational Technology (OT) Security, September 2023, from NIST. Section 5.2.3.1, Network Architecture, describes grouping components into levels, tiers or zones as a precursor to applying isolation devices that protect and monitor communications between them, and applies the same firewall concept to ISA/IEC 62443 architectures. Those boundaries are existing places at which SI-issued actions can be intercepted.
  • Guidance NIST SP 800-207, Zero Trust Architecture, from NIST. Section 3, Logical Components of Zero Trust Architecture, defines the policy enforcement point as the component that enables, monitors and terminates connections between a subject and an enterprise resource, for example as a gateway in front of the resource. An intercept point in this Implementation plays the same role for SI-issued actions.
  • Guidance OWASP Top 10 for Agentic Applications, Version 2026, December 2025, from the Agentic Security Initiative of the OWASP Gen AI Security Project, a volunteer community project of the Open Worldwide Application Security Project. Among its mitigations for ASI08, Cascading Failures, it asks that planning be separated from execution through an external policy engine, and that each high-impact tool invocation be validated against a policy-as-code rule before it runs. This is the guarded-proxy pattern of this Implementation in agentic form.
