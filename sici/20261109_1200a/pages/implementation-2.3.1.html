Implementation 2.3.1: Baseline SI System Performance

Establish a “validated standard” dataset consisting of curated historical inputs into the system, together with inputs representative of the current operating regime, for both normal and known-fault conditions, and expected outputs, and expected levels of performance against this dataset. This dataset should be regularly reviewed and updated to account for drift in the environment, task, and/or expected behavior. Updating the dataset does not preclude also retaining a fixed, version-controlled subset, so that results from successive versions of the AI system remain comparable. Keep this dataset separate from the data used to train or fine-tune the AI system, and re-check that separation after each retraining, so that measured performance is not inflated by examples the system has already seen. Where the data comes from physical assets, separate it by asset rather than only by time window, since records from the same asset in different periods can be correlated. AI systems should be regularly tested against this dataset during scheduled intervals as defined in Implementation 2.3.4: Recurrent Risk Evaluations and deviations from acceptable thresholds for performance should be flagged for review and remediation as necessary. When the AI system is retrained or adjusted, testing the previous and the adjusted versions against this dataset can show whether the change is an improvement before the adjusted version replaces the previous one. For resource-constrained environments, a minimal implementation is offline replay of recorded process-historian data covering both normal and known-fault conditions, which uses data many operators already hold and needs no access to the live process.

Record with each test run the version and configuration of the AI system tested, including any prompts and retrieval sources, and the version of the dataset used, so that results from different runs can be compared. Where repeated runs against the same dataset give different results, record that variation alongside the result. Keeping versioned datasets and run records has a storage and curation cost, which bears on how many versions are kept and for how long.

References:

  • Standard ISO/IEC 22989:2022, Information technology: Artificial intelligence: Artificial intelligence concepts and terminology, from ISO and IEC. Clause 5.11.8, Validation and test data, states that test data are never shown to the model during training, because a model given training data for testing can remember the correct prediction without processing the sample, which bears on keeping the validated standard dataset separate from training and fine-tuning data.
  • Regulation DoD Manual 5000.101, “Operational Test and Evaluation and Live Fire Test and Evaluation of Artificial Intelligence-Enabled and Autonomous Systems,” December 9, 2024, a policy issuance of the United States Department of Defense, binding on DoD components. Paragraph 3.2.b.(1)(a) requires independent test datasets that share no instance with the training, validation or test sets, are operationally representative, and include out-of-distribution examples for changing operational and environmental conditions. Outside DoD, this Implementation suggests the same separation and the same coverage of current operating conditions.
  • Guidance Supervisory Guidance on Model Risk Management, SR Letter 11-7 Attachment, April 4, 2011, from the Board of Governors of the Federal Reserve System and the Office of the Comptroller of the Currency. Section V.3, Outcomes Analysis, describes back-testing as comparing actual outcomes with model forecasts over a period not used in model development, and states that analysis of holdout samples is not a substitute for it. It also describes parallel outcomes analysis, in which the original and adjusted models are both tested against realized outcomes before the adjusted model replaces the original. Written for banking organizations, it bears on keeping the dataset separate from development data and on comparing versions after retraining.
