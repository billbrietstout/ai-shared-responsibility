Implementation 11.3.2: Maintain Isolated Standby Infrastructure and Allocated Reserves

Standby infrastructure that does not fail along with the SI system gives an organization somewhere to run essential functions during an outage. Set aside dedicated backup infrastructure for fail-over to systems that share as little as practical with the primary SI system. Periodically confirm that this infrastructure still functions and remains as isolated as practical from the primary SI system’s failure modes. Judge that isolation by looking for single points of failure and for resources the standby shares with the primary SI system. Convergence onto shared platforms can undermine this isolation. For example, an organization that runs its phone system over the same network as email and messaging cannot count them as alternate communication paths. Shared administration is another such resource: where standby or backup infrastructure is managed through the same privileged accounts as the primary environment, it may not give the protection intended. Keep known-good copies of the configurations and control logic the standby infrastructure needs, stored where they can be retrieved and loaded without relying on the primary SI system’s environment. These copies need updating whenever the configuration or control logic changes, which adds maintenance overhead. How much budget to hold in reserve for it, and for which outages a controlled shutdown under Implementation 11.2.4: Unplanned Shutdown and Controlled Isolation Protocols is planned instead, is for the organization to decide, within any regulatory or contractual obligations; record the choice and the outage durations it assumes. The known-good copies hold the configuration and control logic an attacker would need to understand or alter the process. The record of shared resources shows where the standby is least isolated. Protect both under the organization’s existing information classification and handling practice.

Decisions for the Organization:

  • Which resources, such as networks or privileged administration accounts, does the standby infrastructure still share with the primary environment, and is that accepted?

References:

  • Guidance NIST SP 800-160v2r1, Developing Cyber-Resilient Systems: A Systems Security Engineering Approach, from NIST. Section D.5.2.6, Maintain Redundancy, notes that redundancy requires the redundant resources to be protected, and that it should be applied together with diversity because malware can propagate across homogeneous resources. It establishes the extent of redundancy through analysis that looks for single points of failure and shared resources, and warns that trends to convergence can undermine it, which bears on confirming that standby infrastructure stays isolated from the primary SI system’s failure modes.
  • Guidance Principles of operational technology cyber security, 2024, from the Australian Signals Directorate’s Australian Cyber Security Centre, co-sealed by CISA, NSA, FBI and agencies from seven other countries. Principle 4, Segment and segregate OT from all other networks, notes that if backups or backup infrastructure for the OT environment are managed by privileged corporate IT accounts, the desired level of risk mitigation against a cyber incident may not be provided. It asks organizations to regularly assess the risk of insufficiently separating administrative and management systems, which bears on the shared resources this Implementation looks for.
  • Guidance NIST SP 800-53r5, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement CP-9(3), Separate Storage for Critical Information, stores backup copies of critical system software and other security-related information in a separate facility or a fire rated container that is not collocated with the operational system. It bears on holding the standby infrastructure’s known-good configurations apart from the primary SI system’s environment.
  • Guidance NIST IR 8183A Volume 1, Cybersecurity Framework Manufacturing Profile Low Impact Level Example Implementations Guide: General Implementation Guidance, September 2019, from NIST. Section 6.8, Configuration Backups, says that configuration backups “allow the manufacturer to restore device configuration settings from a known good state from a specific point in time”, for “quick recovery to a known operational state when incidents occur”. This bears on keeping known-good copies of the configurations and control logic the standby infrastructure needs.
