Implementation 7.3.1: Maintain a Registry of SI Systems and Changes

A registry of versions and changes helps the organization know which configuration was in service at a given time, and so trace outputs back to it. The registry should uniquely identify the specific versions of the AI systems and models, versions of prompt templates, and the specific “if/then” safety logic used for output filtering. Document every change to these safety parameters in a centralized change log that identifies the person who authorized the change and the technical justification. The registry and change log describe the safety logic in detail and name who may change it, so they warrant the same protection as the sensitive system prompts in Task 7.3: Manage Version Control and Logging for Internal SI Safety Mechanisms. Keep earlier versions retrievable, so that an investigation can establish which model, prompt template and safety logic were in force when a given output was produced. Keeping every version carries storage and management overhead, especially for systems that change often. How long to keep them is for the organization to decide, within any regulatory or contractual obligations (see Task 10.1: Define Decision-Level Logging and Metadata Retention Policies).

References:

  • Guidance AI Incident Response Framework, Workstream 2: Preparing Defenders for a Changing Cybersecurity Landscape, version 1.0, 27 October 2025, from the Coalition for Secure AI, an OASIS Open Project. Section 3.3.1, Preparation Phase, lists system prompt versioning and configuration management among monitoring considerations, with guidance to maintain an auditable prompt history and to track all model versions and parameters. Section 3.3.3.1 adds that forensic analysis needs to retrieve the system prompt and other parameters used when interacting with a model. Both bear on the registry this Implementation asks for.
  • Guidance Artificial intelligence and machine learning: Supply chain risks and mitigations, 2025, from the Australian Signals Directorate, co-sealed by national cyber security agencies of Canada, Japan, the Republic of Korea, New Zealand, Singapore, the United Kingdom and the United States (the National Security Agency). The machine learning models section, under model verification and provenance, asks that a model registry be kept of the specific model versions that have been verified, tested and approved for use, and that each new version be verified and tested before approval. This is the model side of the registry this Implementation asks for.
