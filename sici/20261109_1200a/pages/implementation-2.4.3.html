Implementation 2.4.3: Technical Accuracy and “Plausible Hallucination” Audits

Implement specific TEVV protocols to identify plausible-sounding but technically inaccurate outputs. For AI systems providing or generating diagnostics, maintenance summaries, operational advice, procedures, code, or configurations, use subject matter experts to at least spot-check and/or assist in red-teaming the system’s instructions. This testing should focus on edge cases where the AI might generate incorrect maintenance steps that appear valid on the surface but would damage physical assets or violate safety protocols if executed. Where the consequence of an incorrect procedure or configuration warrants it, treat this audit as a release gate: measure the rate of plausible but incorrect outputs on a defined set of domain cases, set the acceptable rate in advance under Implementation 1.3.1: Define TEVV Scope and Requirements per SI System, and track it across changes to the model, prompts and retrieved material. For AI-generated code, test cases can include checking that each software package the code names exists and is the one intended. Code-generating systems can name packages that do not exist, and a name that does resolve may not be the package intended: it may be an unrelated or unmaintained package with a similar name, or a malicious one that an adversary has published under that name. Test cases can include questions the AI system should not be able to answer, such as questions about equipment the site does not have, questions just outside its retrieval sources, questions about guidance that was current when the model was trained but is no longer correct, or requests for exact values that no available source gives, to check whether it identifies the limits of what it knows rather than producing an answer. Audits can also sample outputs produced in service, weighted toward the output types with the greatest consequence.

References:

  • Guidance NIST AI 600-1, Artificial Intelligence Risk Management Framework: Generative Artificial Intelligence Profile, from NIST. Section 2.2, Confabulation, names and defines the failure this Implementation tests for, including outputs that diverge from the prompt or contradict earlier statements in the same context, and describes it as “a natural result of the way generative models are designed”.
  • Guidance NIST AI 100-2e2025, Adversarial Machine Learning: A Taxonomy and Terminology of Attacks and Mitigations, from NIST. Section 3.4.2, Integrity Attacks, covers indirect prompt injection that drives a generative system to produce incorrect summaries of its sources or to return attacker-specified content, and notes that these attacks often disrupt the model’s behavior in subtle ways that may not be obvious to the end user. It is the attacker-induced counterpart of the plausible but technically inaccurate outputs this Implementation audits for, and a reason for subject matter experts to red-team as well as spot-check; outputs that are wrong with no attacker present are outside its scope.
  • Research We Have a Package for You! A Comprehensive Analysis of Package Hallucinations by Code Generating LLMs, by J. Spracklen, R. Wijewickrama, A. H. M. N. Sakib, A. Maiti, B. Viswanath and M. Jadliwala, Proceedings of the 34th USENIX Security Symposium, August 2025. Across 576,000 code samples from 16 code-generating models, on average at least 5.2% of the packages named by commercial models and 21.7% of those named by open-source models did not exist. It describes how an adversary can publish a malicious package under a hallucinated name, which bears on dependency checks in audits of generated code.
  • Guidance NIST IR 8312, Four Principles of Explainable Artificial Intelligence, September 2021, from NIST. Section 2.4, Knowledge Limits, states the principle that systems identify cases in which they were not designed or approved to operate, or for which their answers are not reliable, so that a judgment is not provided where it may be inappropriate. This bears on test cases that check whether the AI system declines questions it cannot answer reliably.
