Implementation 8.1.1: Evaluate SI Applications

Finding forensic gaps before an incident, rather than during the investigation that follows one, gives the organization time to close them or plan how to compensate. Evaluate AI applications to identify the extent of root cause analysis required to satisfy risk management and regulatory requirements. This evaluation should explicitly screen for process paths where deterministic forensic reconstruction is a safety or operational requirement. For each application, the evaluation can record the facts that decide whether reconstruction is possible: whether the SI system is run locally or hosted by a provider, whether its version can be held fixed, whether it gives the same output for the same input, and what it can log. Where a model was obtained outside procurement, for example downloaded directly, the facts may depend on what the organization itself recorded about it (see Task 3.7 and Task 7.1). Where a proposed AI system cannot satisfy these specific analytical demands, organizations should either substitute systems inherently capable of true root cause analysis, demonstrably close the gap via validated compensating controls, or implement deterministic boundaries so that execution hands over to manual or legacy systems capable of the required analysis, where such systems are available and maintained (see Task 11.2: Define Manual and Alternative Operating Procedures for Long-Term Mission Continuity).

Decisions for the Organization:

  • Where a proposed SI system cannot meet the reconstruction demands, is it substituted, are compensating controls validated, or does execution hand over to manual or legacy systems?

References:

  • Guidance NIST SP 800-53 Rev. 5, Release 5.2.0, Security and Privacy Controls for Information Systems and Organizations, from NIST. Control enhancement SI-2(7), Root Cause Analysis, added in Release 5.2.0, calls for root cause analysis of issues and failures, and its discussion has organizations choose the analysis method according to incident severity. That is the proportionality this Implementation applies when deciding the extent of root cause analysis each AI application must support. The control does not itself require deterministic reconstruction; whether an AI system can support that is the further question this Implementation screens for.
