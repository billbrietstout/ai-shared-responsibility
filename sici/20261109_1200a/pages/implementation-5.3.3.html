Implementation 5.3.3: Separate Privilege via Encapsulated Downstream Agents and Tools

Routing high-consequence actions through a separate, trusted tool or agent helps keep their execution under controls that do not depend on a complex SI system behaving well. Avoid granting complex, probabilistic, adaptive AI agents and systems, and those with exposure to untrusted inputs, direct access to high-consequence actions on sensitive assets (e.g., write access to PLCs, databases, or emergency controls). Instead, such AI agents or systems should issue structured requests to specialized downstream “proxy” tools or agents that hold the necessary execution credentials and maintain their own independent validation logic, parameter collars, state checks, and safety constraints described in Task 3.2: Implement Independent Guardrails for SI Outputs.

Note that this necessarily implies that the downstream, or delegated, tool or agent should have permissions that the upstream, delegating agent or system does not have. This structural separation helps to prevent an AI model hallucination, prompt compromise, or other risks associated with the more complex AI system from resulting in out-of-bounds physical or digital actions. Execution authority is mediated by a downstream agent or tool that is trusted, and controlled, to exercise it. This is often a deterministic, single-purpose boundary, but not necessarily so. For shared assets, it also avoids relying on the built-in guardrails of each upstream AI agent or system. Such an intermediary need not only grant or refuse a request. It can also remove unauthorized parameters, hold a setpoint to its permitted range, or strip credentials, system topology details and personal data from the payload before passing it on. Modifying a request in this way can keep an agentic workflow running where refusal would halt it. Where a request is altered rather than refused, recording the alteration and informing the requesting SI system can avoid it acting as though the request ran as issued. Separation moves the reliance onto the downstream tool or agent rather than removing it, so its validation should itself be tested, including with malformed, out-of-scope and adversarially crafted requests.

Decisions for the Organization:

  • Which high-consequence actions go through a downstream tool or agent, and may it modify a request or only grant or refuse it?

References:

  • Guidance NIST AI 100-2e2025, Adversarial Machine Learning: A Taxonomy and Terminology of Attacks and Mitigations, March 2025, from NIST. Section 3.4.4 observes that current mitigations do not offer full protection against indirect prompt injection, so application designers may assume prompt injection is possible whenever a model is exposed to untrusted input and design accordingly, for example by using multiple models with different permissions or allowing interaction with untrusted sources only through well-defined interfaces. This Implementation applies that design response to execution authority over sensitive assets.
  • Guidance OWASP Top 10 for Agentic Applications, Version 2026, December 2025, from the Agentic Security Initiative of the OWASP Gen AI Security Project, a volunteer community project of the Open Worldwide Application Security Project. Entry ASI03, Identity and Privilege Abuse, lists Cross-Agent Trust Exploitation (Confused Deputy) among its common examples: a compromised low-privilege agent relays valid-looking instructions to a high-privilege agent, which executes them without re-checking the original user’s intent. This is the failure that the downstream tool’s own validation in this Implementation guards against.
