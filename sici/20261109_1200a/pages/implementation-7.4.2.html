Implementation 7.4.2: Implement Regular Integrity Checks for Systems that Interface with External SI Services

Because behavior observed in testing may not continue after a provider changes an external SI service, regular checks help an organization know whether its test results still apply. Integrity checks should verify that external AI systems and services have not been unexpectedly altered. This may incorporate TEVV protocols such as those from Task 2.3: Establish Protocols for and Regularly Perform Systematic and Achievable Testing, Evaluation, Validation, and Verification (TEVV). Checks can include re-verifying signatures, hashes and declared versions where the service exposes them, and monitoring behavior for change. A provider may modify serving infrastructure without notice, in ways that change model behavior subtly. Contractual terms that require notice of version updates can help, but a provider may not give notice of changes it considers immaterial. Behavioral checks can reuse the validated standard dataset of Implementation 2.3.1: Baseline SI System Performance, run on a schedule and after any notified change, with results compared against those recorded when the service was validated. The validated dataset, and the size of difference that triggers review, tell an attacker how far a service’s behavior can be shifted without detection. Protecting them is a matter for the organization’s existing information classification and handling practice. An unexplained difference can be treated as a change and reviewed under Implementation 7.4.1: Define and Implement Requirements for Approvals and Logging of Updates and Changes to SI Systems.

Decisions for the Organization:

  • How often are integrity checks on external SI services run, and what size of difference triggers review?

References:

  • Guidance Establish Risks and Controls for the AI Supply Chain, version 1.0, 12 June 2025, from Workstream 1, Software Supply Chain Security for AI Systems, of the Coalition for Secure AI, an OASIS Open Project. Section 3.1.4, AI Infrastructure Supply Chain Security, lists infrastructure configuration drift among the concerns when consuming hosted models: third-party providers may modify serving configurations without notice, changing model behavior in subtle ways that downstream consumers cannot detect. This is the case the integrity checks in this Implementation address.
  • Guidance OWASP Top 10 for Agentic Applications, Version 2026, December 2025, from the Agentic Security Initiative of the OWASP Gen AI Security Project, a volunteer community project of the Open Worldwide Application Security Project. Entry ASI04, Agentic Supply Chain Vulnerabilities, asks in its continuous validation mitigation that signatures, hashes and SBOMs, including AIBOMs, be re-checked at runtime, and that behavior, privilege use and lineage be monitored for anomalies. These are checks this Implementation can include.
  • Guidance OpenSSF Model Signing (OMS) Specification, Version 1.0, from the AI/ML Working Group of the Open Source Security Foundation, a cross-industry body hosted by the Linux Foundation; checked against commit 91bf841, October 2026. It defines a detached signature file, distributed with the model, that lists a digest for every file in the model directory, and a verification procedure that by default fails if any file has changed or any unlisted file is present (Sections 8.4 and 8.5). Its README notes that signing verifies only that a model has not changed since it was signed, not its quality or security. This is one way to make the integrity check in this Implementation verifiable for models the organization holds locally.
  • Commentary Artificial Intelligence Model Risk Management: Observations from a Thematic Review, Information Paper, December 2024, from the Monetary Authority of Singapore, written for banks. Section 6.5, under Change Management, observes that most banks have set up processes for third-party SI providers to notify them of version updates, and a footnote records that a provider may not notify end users of changes it views as immaterial. This is the gap the integrity checks in this Implementation cover.
