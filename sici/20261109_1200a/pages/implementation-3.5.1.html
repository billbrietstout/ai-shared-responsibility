Implementation 3.5.1: Map Direct Functional and Algorithmic Dependencies

A map of where SI outputs go helps an organization plan monitoring, containment, and recovery before an error spreads. Trace and document downstream logical, algorithmic, and operational paths of AI outputs to identify how errors, whether in control outputs, direct executable code, or human-mediated summaries, could trigger a chain reaction through connected assets. These dependencies often extend beyond traditional IT/OT/ICS boundaries; for example, an AI agent defending an IT network might erroneously disable authentication traffic, physically locking personnel out of a facility. To capture these risks more fully, organizations should conduct a high-value asset (HVA) assessment that extends outward to map functional dependencies on upstream suppliers and downstream customers. This can help limit how far automated errors propagate along the extended supply chain. Include undeclared consumers, such as systems or spreadsheets that read the SI system’s outputs without its owner’s knowledge, and algorithmic couplings, where two automated systems, possibly operated by different organizations, react to each other’s outputs and form a feedback loop that neither owner sees. For each dependency, record what the downstream system does if the SI output it receives is wrong, late or missing, and whether a person reviews that output before it takes effect. Treat a dependency found in testing or operation that is not on the map as a finding, and update the map when the SI system or a connected system changes.

Decisions for the Organization:

  • How far upstream and downstream, including outside the organization, does the dependency map reach?

References:

  • Guidance NIST SP 800-160v2r1, Developing Cyber-Resilient Systems: A Systems Security Engineering Approach, from NIST. Section 3.2.3.1, Identify Critical Resources, Sources of Fragility, and Attack Surfaces, identifies critical resources from functional flows and mission threads, noting that a resource can be critical at one point in a flow and not at another, and notes that network or graph analysis can show how tightly elements are connected and that graphical analysis of the distribution of component types can help determine how easily a given stress could propagate, an approach this Implementation adapts to errors in AI outputs.
