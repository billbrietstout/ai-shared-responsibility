Implementation 3.4.4: Define Runtime Anomaly Escalation Procedures

Escalation criteria help a sustained or recurring anomaly reach people who can investigate and respond, while the evidence is still intact. Extend communications actions defined under Implementation 3.2.4: Define Further Logging and Communication Actions to cover sustained or recurring behavioral anomalies of AI systems. Define the criteria at which a sustained or recurring anomaly is escalated for investigation as a possible incident, and at that point hand it to the procedures in Practice 8: Incorporate SI-Aware Incident Analysis and Response Procedures. Where an anomaly could reflect either drift or deliberate interference, preserve the relevant records and system state before recalibrating or retraining the model, so that the cause can still be investigated. Preserving state has a storage and handling cost. How long it is kept can follow the retention decided under Task 10.1: Define Decision-Level Logging and Metadata Retention Policies, and the preserved records should identify the model version, prompts, configuration, and other state and information that influenced the output (Implementation 10.1.5: Define What Each Operational Record Is For).

Decisions for the Organization:

  • At what point is a sustained or recurring anomaly escalated as a possible incident?
  • While the cause is unclear, is the baseline held and the anomaly escalated, or does operation continue under tightened constraints? (see the Secure versus Reliable tension in Task 3.4: Monitor for Anomalous SI Behavior)

References:

  • Guidance NIST SP 800-61r3, Incident Response Recommendations and Considerations for Cybersecurity Risk Management, April 2025, from NIST. In Table 3, subcategory DE.AE-08 has incidents declared when adverse events meet defined incident criteria, and the notes to RS.MA ask that triage, prioritization, escalation and elevation be based on a set of risk evaluation factors. These are the criteria this Implementation asks to be defined for SI anomalies. Subcategory RS.AN-07 asks that incident data and metadata be collected with their integrity and provenance preserved, which bears on preserving records and state before recalibration.
  • Guidance AI Incident Response Framework, Workstream 2: Preparing Defenders for a Changing Cybersecurity Landscape, version 1.0, 27 October 2025, from the Coalition for Secure AI, an OASIS Open Project. Section 3.3.2, Detection and Analysis Phase, lists escalation triggers among the manual review elements, and asks responders to validate whether anomalous behavior constitutes a security incident and to make escalation procedures match incident severity.
