Implementation 8.1.3: Update Existing Incident Response Policies and Playbooks

Include documenting the state of AI systems at the time of the incident, such as information from Task 7.1: Maintain an Internal Registry of SI Deployments. Playbooks should also cover the failure states that an SI system introduces, including how to bypass or replace it. Bypassing or replacing the SI system is available only where the organization has prepared the alternative in advance (see Task 11.2: Define Manual and Alternative Operating Procedures for Long-Term Mission Continuity). It brings its own considerations, such as reduced capacity or the loss of a protective function the SI system was performing. Where a containment step would reset an agent’s memory, purge conversation history or revert a model version, the playbook can call for state such as copies of the model weights or version, prompts and retrieval store state to be preserved first, so that containment does not remove what reconstruction needs. Keeping such copies carries storage and handling overhead, and for a hosted system it may need the provider’s cooperation, which can be agreed in advance (see Task 8.5: Pre-Arrange Specialized Resources for Investigating and Recovering from SI Incidents). Deciding in advance which SI system state to preserve, and under what conditions, can help responders act quickly when containment is urgent. The playbook should name who preserves the SI system’s state, such as the point of contact for the SI system under Implementation 8.3.1: Identify Internal Incident Management Points of Contact, or its provider for a purchased-as-a-service system.

Decisions for the Organization:

  • Who preserves SI system state, and which state is preserved before containment, under what conditions?

References:

  • Guidance Cybersecurity Incident & Vulnerability Response Playbooks: Operational Procedures for Planning and Conducting Cybersecurity Incident and Vulnerability Response Activities in FCEB Information Systems, November 2021, from the Cybersecurity and Infrastructure Security Agency (CISA). In the Incident Response Playbook, the containment considerations include any impact on the collection, preservation, securing and documentation of evidence. The checklist in Appendix B asks responders to weigh the requirement to preserve evidence when choosing a containment strategy, and to make system backups to preserve evidence. Written for federal civilian agencies and cyber incidents, it is a model for the playbook steps that this Implementation extends to SI system state.
  • Guidance NIST SP 800-86, Guide to Integrating Forensic Techniques into Incident Response, August 2006, from NIST. Section 5.2.1, Collecting Volatile OS Data, notes that powering off a system, or even disconnecting it from a network, can remove the chance to collect volatile data, and that the criteria for deciding whether to preserve it should ideally be documented in advance. Written about operating system memory, it bears on SI system state, such as agent memory or conversation context, that is held only in a running system.
  • Guidance AI Incident Response Framework, Workstream 2: Preparing Defenders for a Changing Cybersecurity Landscape, version 1.0, 27 October 2025, from the Coalition for Secure AI, an OASIS Open Project. Section 3.3.3 lists containment steps for each architecture, such as resetting memory and purging conversation history, and under Evidence Preservation asks for forensic copies before containment, including vector database state and model weights. Section 3.3.3.1 adds that system and user prompts, parameters and raw outputs need to be retrievable by the investigator. These are the SI system state that this Implementation adds to incident playbooks.
  • Guidance Principles for the Secure Integration of Artificial Intelligence in Operational Technology, December 2025, joint guidance from nine national cybersecurity agencies across seven countries, led by CISA. Section 4.2, Embed Safety and Failsafe Mechanisms, asks that the new failure states an SI system introduces, including how to bypass or replace it, be incorporated into existing functional safety and incident response processes, which is the playbook update this Implementation describes.
