Scenario B.31: Portal SI assistant with broad retrieval access

Scenario. A company’s online portal includes an SI assistant with retrieval access to many back-end databases, built on an open-source component with a known vulnerability. Attackers exploit the component and craft queries that lead the assistant to return personal data, using credentials it stores unencrypted. Monitoring inspects network traffic but not what the assistant retrieves, so the exfiltration continues for months without detection.

Trustworthiness Characteristics: Secure, Privacy-Enhanced

Critical Infrastructure Sector: Multiple sectors

How the Practices apply:

  • Practice 5: Implement Identity and Access Management (IdAM) for SI Agents, Systems, and Tools: The SI assistant’s stored, unencrypted credentials unlock many back-end databases, far more than any single customer query needs.
  • Practice 7: Manage Internal SI Supply Chain and Data Provenance: A known-vulnerable open-source component in the SI-enabled portal stack is left unpatched, and weak segmentation lets the assistant’s retrieval reach many back-end data stores.
  • Practice 8: Incorporate SI-Aware Incident Analysis and Response Procedures: The portal’s SI assistant is used to exfiltrate data for months without incident analysis that identifies, scopes, and coordinates response to the breach.
  • Practice 10: Implement Multi-Tiered SI System Logging and Audit Capabilities: Monitoring covers network traffic but not what the SI assistant retrieves, so months of data exfiltration go unseen.
